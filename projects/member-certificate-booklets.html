The problem

This customer-facing certificate-document workflow depended on several enterprise services for member, group, and coverage data. Formal performance tests showed a best case of roughly four seconds, P90 near six seconds, and a worst case around 8.5 seconds—well outside a required two-second SLA.

The release date was already committed. The response contract had to remain compatible, all downstream calls remained mandatory, and a broad redesign would have introduced unacceptable risk.

How I approached it

I started with timestamp-based instrumentation rather than assumptions. Timing each major dependency exposed redundant work and showed which calls could safely run after the initial member context was established.

I parallelized independent downstream requests with CompletableFuture, collecting results only after all required work completed. I also cached stable reference data in Redis, eliminating repeated lookups. Each change was verified through repeated performance testing before it moved forward.

Why these decisions

  • Concurrency: independent calls should not extend end-to-end latency by waiting on one another.
  • Redis: low-change reference data benefited from simple cache-aside access.
  • Measurement first: timing data kept the fix targeted and avoided unnecessary complexity.
  • No major redesign: the safest path was to meet the SLA within existing integration and delivery constraints.

Outcome

~75%

reduction in P90 response time
~6s → ~1.5s

The service met its production SLA, reduced unnecessary downstream utilization, and restored confidence in the release path.

What I would improve today

For a new implementation, I would evaluate Java 21 virtual threads for blocking I/O, a dedicated executor rather than the common pool, OpenTelemetry tracing, downstream circuit breakers and bulkheads, plus service-level latency dashboards.

Key lesson

Performance gains often come from understanding dependency relationships—not from prematurely optimizing code. Small, measurable changes can be safer and more effective than a broad rewrite.

Recruiter summary

Diagnosed a production SLA breach with timing data, then cut P90 latency ~75% (6s → 1.5s) using concurrency and Redis caching—without a redesign, on a fixed release date, with zero customer-facing changes.
