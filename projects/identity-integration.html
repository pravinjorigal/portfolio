05 / Identity integration · Life insurance

Secure Authentication with LDAP & Okta

Connected backend registration services to centralized identity providers, supporting secure onboarding without creating a separate, fragmented user-management system.

At a glance

Stack
Java 17, Spring Boot, REST, LDAP, Okta, Oracle, Redis, Splunk
Focus
Secure, centralized identity management

Business context

Digital insurance registration required members to validate customer and policy information, then gain secure access to services. The application had to use the organization’s established identity infrastructure rather than manage accounts independently.

The challenge

Identity provisioning depended on business validation and several downstream systems. Those centrally governed identity systems could not be changed, customer data needed careful handling, and releases followed strict enterprise change control.

My contribution

I developed backend APIs for the journey, mapped requests and responses across LDAP and Okta integrations, validated business information before provisioning, and supported frontend, QA, UAT, and deployment work through consistent contracts.

Solution

The backend coordinated business validation before interacting with enterprise identity services. API contracts were agreed early so frontend development could use mock endpoints while dependencies were still being prepared. Production integrations then replaced the mocks without requiring a consumer-facing contract change.

Why this approach

  • Centralized providers: reduced duplicate user management and aligned account lifecycle with enterprise standards.
  • LDAP: connected to existing centralized directory information.
  • Okta: supported enterprise-grade identity and access workflows.
  • API-first delivery: reduced cross-team waiting and integration risk.

Operational learning

Post-release Splunk analysis helped distinguish application issues from downstream identity-service behaviour. Clear request logging was especially important in a distributed security flow where troubleshooting must remain careful about sensitive information.

What I would improve today

I would add end-to-end correlation, distributed tracing, resilience tests for external identity providers, circuit breakers, enhanced security alerts, and dedicated observability dashboards for provisioning outcomes.

Key lesson

Authentication is only part of identity management. Provisioning, validation, lifecycle coordination, and observability need the same deliberate design attention.

Recruiter summary

Integrated a customer onboarding backend with LDAP and Okta, coordinating business validation with enterprise identity provisioning via API-first contracts—keeping account lifecycle centralized, secure, and observable.
